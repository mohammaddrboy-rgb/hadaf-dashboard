# داشبورد آموزشگاه هدف

داشبورد RTL برای مدیریت صنف‌ها، شاگردان، پرسنل، مالی و گزارش‌های آموزشگاه هدف. داده‌ها روی سرور همگام‌سازی (`server/server.js`) نگهداری و بین همهٔ دستگاه‌ها به اشتراک گذاشته می‌شوند؛ هر مرورگر یک نسخهٔ محلی در `localStorage` هم نگه می‌دارد تا بدون اینترنت هم کار کند.

## ساختار پروژه

```
hadaf-dashboard/
├── index.html            # اسکلت HTML
├── css/app.css           # استایل‌ها
├── js/seed.js            # دادهٔ نمونهٔ اولیه (بدون رمز عبور)
├── js/app.js             # منطق اصلی برنامه و ورود
├── js/discount-codes.js  # کدهای تخفیف مکاتب
├── js/updates.js         # درآمد من، دارایی‌ها، گزارش مالیاتی، چاپ پرونده
├── js/updates2.js        # پیش‌پرداخت، انضباط پرسنل، پروندهٔ شاگرد
├── js/sync.js            # همگام‌سازی با سرور (ادغام سه‌طرفهٔ تغییرات)
├── server/server.js      # سرور داده و ورود (Node.js، بدون وابستگی)
└── assets/logo.png       # لوگو
```

## اجرای محلی

```bash
cd hadaf-dashboard
PORT=8080 HADAF_DATA_DIR=./data STATIC_DIR=. node server/server.js
```

سپس در مرورگر باز کنید: `http://127.0.0.1:8080`

اولین مرورگری که به سرور خالی وصل شود، داده‌های اولیه را روی سرور می‌گذارد و رمزهای تازه‌ساخته‌شده را یک‌بار در صفحهٔ ورود نشان می‌دهد؛ آن‌ها را یادداشت کنید.

بدون سرور هم (مثلاً `python3 -m http.server 8080`) برنامه با دادهٔ همان مرورگر کار می‌کند، اما چیزی به اشتراک گذاشته نمی‌شود.

برای خروجی Excel به CDN کتابخانهٔ SheetJS وابسته است. بدون اینترنت، بخش خروجی Excel کار نمی‌کند.

## نقش‌ها

| نقش | دسترسی |
|-----|--------|
| سهامدار | همه بخش‌ها |
| مدیر شعبه | همه بخش‌ها به‌جز سهامداران |
| مدرس | صنف‌های خودش و برنامهٔ کلی |
| کارمند | پذیرش، ثبت‌نام و امور روزمره |

## امنیت

- رمز عبور هنگام ورود روی سرور بررسی می‌شود و سرور یک نشست (token) می‌دهد. بدون ورود، سرور هیچ داده‌ای نمی‌دهد و تغییری نمی‌پذیرد (به‌جز بارگذاری اولیه روی سرور خالی).
- رمزهای عبور فقط برای سهامداران فرستاده می‌شوند. مدیر، مدرس و کارمند رمزها را دریافت نمی‌کنند و نمی‌توانند رمزها، سهامداران یا دارایی‌ها را تغییر دهند.
- شاگرد فقط پروندهٔ خودش (ثبت‌نام‌ها، حضور و نمرات خودش) را دریافت می‌کند و فقط‌خواندنی است.
- پس از ۲۰ تلاش ناموفق از یک IP یا ۱۰ تلاش ناموفق برای یک حساب در ۱۵ دقیقه، ورود موقتاً مسدود می‌شود.
- همهٔ متن‌های واردشده (نام، توضیحات و …) پیش از نمایش escape می‌شوند.
- محدودیت: مدیر، مدرس و کارمند بقیهٔ داده‌ها (از جمله مالی) را دریافت می‌کنند؛ منوها بر اساس نقش پنهان می‌شوند، اما تفکیک کامل داده به ازای هر نقش روی سرور انجام نمی‌شود.
- حتماً سایت را فقط با HTTPS در دسترس قرار دهید؛ در غیر این صورت رمزها و token روی شبکه قابل شنود هستند.

## استقرار

فایل‌های استاتیک را روی وب‌سرور قرار دهید و `server/server.js` را (مثلاً با systemd) اجرا کنید؛ nginx مسیر `/api/` را به آن proxy می‌کند. هدر `X-Real-IP` لازم است تا محدودیت تلاش‌های ورود برای هر کاربر جدا حساب شود.

مثال Nginx:

```nginx
server {
    listen 443 ssl;
    server_name hadaf.example.com;
    root /var/www/hadaf;
    index index.html;
    client_max_body_size 30m;

    location /api/ {
        proxy_pass http://127.0.0.1:8791;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Authorization $http_authorization;
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

مثال systemd (`/etc/systemd/system/hadaf-sync.service`):

```ini
[Service]
Environment=PORT=8791 HADAF_DATA_DIR=/var/www/hadaf-data
ExecStart=/usr/bin/node /var/www/hadaf/server/server.js
Restart=always
```

داده‌ها در `HADAF_DATA_DIR` هستند: `db.json` (همهٔ داده‌ها)، `meta.json` (نسخه) و `sessions.json` (نشست‌ها). از این پوشه نسخهٔ پشتیبان منظم بگیرید.
